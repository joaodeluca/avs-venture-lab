Quais arquivos são aceitos?

São três JSONs normalizados, não exports brutos do Stripe, Orb ou outro fornecedor. Você precisa declarar completude e corte; esta ferramenta não autentica nem comprova essas declarações.

  1. Contrato: mesmo cliente, moeda, período UTC, corte e preço constante por unidade para cada medidor.
  2. Eventos: ID, medidor, unidade, quantidade decimal como texto, horários de ocorrência/recebimento. Estornos referenciam uso original.
  3. Fatura: uma linha por medidor, quantidade e valor com exatamente duas casas. Ausência de linha significa zero informado.

Período [início, fim); fim excluído. Arredondamento half-up por total de medidor, não por evento. Sem faixas, franquia, créditos gerais, descontos, impostos, conversão cambial ou preço alterado no período.

Use os templates de contrato, eventos e fatura. Eles estão incompletos de propósito; não os apresente como dados reais. Remova nomes, e-mails e identificadores pessoais; use IDs opacos.

02 / RESULTADO

Uma diferença é um candidato à revisão, não dinheiro recuperado, obrigação de cobrança ou autorização para alterar a fatura.

Relatório identifica os textos de entrada com SHA-256 quando disponível. Hash não comprova autenticidade. Aceite externo não observado. Recálculo JavaScript local; pacote Python original disponível para conferência independente.

O QUE FAZER COM O RESULTADO

01

Conferir a base

Valide período, corte e export completo. Eventos desconhecidos, atrasados ou estornos inválidos bloqueiam valores.

02

Explicar a diferença

Compare quantidade e preço por medidor. Repetições idênticas entram uma vez; repetições conflitantes interrompem a análise.

03

Revisar antes de agir

Leve o relatório ao responsável pelo fechamento. Não há correção automática, cobrança ou integração com seu sistema.

Ferramenta gratuita experimental. Contratos lineares apenas. Não é auditoria contábil certificada.
