01 / SELECIONE O FLUXO

Export JSON

Use apenas um export que você está autorizado a analisar. O relatório baixado omite nomes, URLs e valores dos parâmetros.

Qual recorte é analisado?

Cadeia única com início manual, até oito nós e sem ramificação. Nós reconhecidos: Manual Trigger v1, No Operation v1, Set v3–3.4 com valores literais e HTTP Request v4–4.3 GET sem autenticação/opções. Versões e parâmetros diferentes exigem revisão. Reconhecer um nó não prova que o comportamento será preservado.

03 / SAIA COM UMA TRANSFORMAÇÃO LOCAL

De Set literal a um arquivo Python.

Exemplo original pronto para execução local: Python · entrada fictícia · saída esperada. Leia o código e use python3 extraction-example.py < extraction-input.json. O modelo é explícito; nenhuma equivalência n8n foi demonstrada.

Para uma cadeia manual com NoOp e Set v3.4 literal, prepare uma transformação offline e compare sua saída nesta aba. O export precisa indicar mode: manual e includeOtherFields explicitamente; nenhum default ausente é adivinhado. HTTP e os demais nós não são extraídos.

A triagem acima e a geração offline têm recortes diferentes.

ANTES DE REESCREVER
Um plano de revisão,
sem aprovação automática.
Uma cadeia simples pode esconder dependências nos dados, defaults e falhas do runtime. “Candidata estrutural” indica somente que esta inspeção não encontrou bloqueios reconhecidos.
  • Segredos, nomes de credenciais, expressões, código, ramificações e nós fora do recorte produzem alertas.
  • O arquivo não autentica a sua origem. Valores omitidos, referências externas e segredos disfarçados não são certificados.
  • O relatório descreve o que precisa de confronto com execução autorizada no sistema original. A triagem estrutural não gera código. O workspace abaixo prepara Python apenas para Set literal com retenção explícita, dentro do modelo offline descrito.
  • Uma requisição GET também pode ter efeitos na API de destino. Esta ferramenta não a executa.
